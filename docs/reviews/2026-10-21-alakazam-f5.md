## Before the operator's live check

No finding is a blocker. The README question, the four example questions and the golden set's paths are sound in the
code. Three should-fix items are cheap and decide what the live check shows or can diagnose, so they should go in
before the deploy: **#1** (a failed model call leaves no cause in the logs, so an IAM or model-access failure on the
live check cannot be told apart), **#2** (a lookup of a missing id can never be a clear miss) and **#3** (a question
that names a contractor gets a confident "no matches"). The other should-fix items (#4 to #6) and every nice-to-have
can ship with the next deploy, as the operator's gate on README criteria allows.

## What conforms

- Runtime (items 13, 14, 16): a `ToolLoopAgent` from the tracing facade on `us.anthropic.claude-sonnet-4-6`, wrapped with
  the kit's prompt-caching middleware and then the turn budget; `maxRetries: 0`, `stopWhen: isStepCount(6)`, 700 output
  tokens a step and 1,500 a turn; one retry only on throttling or 5xx with time left; the 25 s deadline counts from
  `requestContext.timeEpoch`, so a cold start is inside it, under the 29 s Lambda timeout.
- Tools (items 18, 19, 22): explicitly registered, typed, mirroring the frozen MCP registry's bounds; pipeline failures
  come back as results with the pipeline request id; one log line per call with free text hashed; `create_lead` refuses
  ids no tool returned in this turn (tested) and runs on the user's message, never on tool text.
- Grounding (items 8, 17): evidence built server-side from tool results; the citation check covers tokens, bare permit
  numbers, contractor keys, "property <id>" mentions and CIDs over the answer and the model's assumptions together, and
  a failure drops all model text; the sanitizer strips HTML, images, links and bare URLs; `answered` and `no_matches`
  need a successful call; response shape, outcomes and typed limitations match the 2026-10-17 entry.
- Privacy and safety (item 9): `owner_name` and the mailing address never reach the projection (`PERSON_KEYS` is the
  trace backstop); lead notes never reach the model or the logs; tool strings are stripped of control, zero-width and bidi
  characters, capped, and declared data in the prompt; the page renders text nodes only, with chips built from server
  evidence; logs carry ids, counts, timings and hashes.
- Infrastructure: its own function (reserved 5) and route (0.5/s, burst 3); Bedrock `InvokeModel` on the profile and the
  three foundation-model ARNs, the same grant the pipeline's chat runs on live in this account; `GetSecretValue` on
  `pidgeot-agent/langsmith-api-key-??????` only; no `DeleteItem`; the deploy script writes the key from a 0600 file,
  never argv; `AgentErrors`, `AgentThrottles`, `ChatFailed` and `ChatDailyTokens` alarms; errors carry `requestId` in the
  body and `x-request-id` in the header, and the page falls back to `apigw-requestid`.
- LangSmith (item 15): enabled, degrading to the plain AI SDK on any failure, `session_id` grouping, cache metadata, flush
  inside the deadline; `LANGSMITH_API_KEY_SECRET_ID` instead of the kit's `_SECRET_ARN` and the SDK's default endpoint are
  recorded (`docs/decisions.md:739-741`, `docs/runbook.md:135`).
- Items 2, 3, 4 and 25 remain README override or Not applicable as decided: no index, embeddings, OpenSearch, thresholds
  or review queue here. The pinned contract has no `mode` on `/v1/permits/text-search` and no `retrieval` block on
  `/v1/meta`, so the 2026-10-16 entry's "adopt it if the pipeline adds a hybrid mode" has nothing to adopt yet.

## Verdict

The built agent is a faithful, well-guarded port of the pipeline's T9 agent with the CRM's lead tools, and it meets
README AC 9 in the code: the README question resolves Austin, runs `search_permits` with `min_open_years` 5 and answers
from cited, server-checked rows. No finding blocks the deploy. Fix #1 to #3 before the operator's live check: they are a
few lines each, #1 makes any live failure diagnosable from CloudWatch, and #2 and #3 turn two plausible evaluator
